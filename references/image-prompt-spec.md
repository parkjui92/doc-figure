# 이미지 모델 경로 — 프롬프트 설계와 점검

`scripts/gen_image.py` 가 하는 일과, 손으로 프롬프트를 쓸 때(키 없이 ChatGPT에 붙여 넣을 때)의 규격.

## 전제가 바뀌었다 — 그러나 검수는 그대로

v1.0은 "이미지 모델은 한글 라벨을 반드시 깨뜨린다"를 전제로 도식에서 이미지 모델을 배제했다. 당시 확산모델에서는 사실이었다.

2026-09 실측에서 이 전제가 최신 GPT Image 모델에서는 더 이상 맞지 않았다.

| 시험 | 모델 | 한글 라벨 | 시간 | 출력 토큰 |
|---|---|---|---|---|
| 4단계 프로세스 (라벨 18) | gpt-image-2 | 18/18 정확 | 77초 | 5,488 |
| 같은 프롬프트 | gpt-image-2.5-sunburst | 18/18 정확 | 27초 | 1,372 |
| 추진체계 (20) | 2.5-sunburst | 20/20 | 25초 | 1,372 |
| 판정 히트맵 (39) | 2.5-sunburst | 39/39 | 31초 | 1,372 |
| 간트 + 코드 렌더 참조 (44) | 2.5-sunburst | 44/44 | 32초 | 1,372 |

**그래도 코드 렌더가 기본이다.** 이유는 셋.

1. **보장이 아니라 확률이다.** 다섯 번 다 맞았다는 것이 여섯 번째를 보장하지 않는다. 숫자 하나(48억 → 46억)가 틀리면 문서 전체의 신뢰가 무너진다
2. **수정 비용이 다르다.** 코드 렌더는 spec 한 줄, 이미지 모델은 수십 초 + 다시 검수
3. **재현성.** 같은 spec이 같은 그림을 내야 개정판에서 그림이 흔들리지 않는다

그래서 이미지 모델은 **"같은 spec을 더 풍부하게"** 뽑는 선택 경로이고, 결과는 **반드시 사람(또는 Claude)이 라벨을 하나씩 읽어 대조**한다.

## 언제 쓰는가

| 쓴다 | 쓰지 않는다 |
|---|---|
| 표지·요약면 등 한 장의 완성도가 중요한 자리 | 개정이 잦은 그림 (일정이 계속 바뀌는 간트 등) |
| 카드마다 의미 있는 선 아이콘이 들어가면 좋을 때 | 수치가 빽빽한 표 (오류 하나가 치명적) |
| 코드 템플릿으로는 안 나오는 질감·리듬이 필요할 때 | 사용자가 한글 편집기에서 직접 고칠 그림 |
| 사용자가 "더 다양하게"를 프리셋 교체로도 만족하지 못할 때 | 키가 없을 때 (→ `--dry-run` 프롬프트만 제공) |

## 세 가지 모드

| 모드 | 명령 | 배치 정확도 | 표현 자유도 | 쓰는 곳 |
|---|---|---|---|---|
| 새로 생성 | (기본) | 중 | 높음 | 조직도·프로세스·논증 도해 등 구조가 단순한 것 |
| 렌더 참조 | `--from-render` | **높음** | 중 | 간트·히트맵·병목 매핑 등 좌표가 중요한 것. 코드 렌더를 참조 이미지로 넘기고 "배치·글자는 그대로, 마감만" 지시 |
| 부분 수정 | `--fix IMG --instruction "…"` | 원본 유지 | — | 글자 하나·색 하나가 틀렸을 때. 전체 재생성보다 싸고 안전 |

## 프롬프트 설계 — `build_prompt` 의 다섯 절

손으로 쓸 때도 이 순서를 지킨다. `--dry-run` 으로 실물을 볼 수 있다.

**① 목적 한 줄** — `Create a finished diagram figure for a Korean policy / research document (landscape, print quality).`

**② LAYOUT** — 세 겹으로 쓴다.
- *제목·부제*: 원문 그대로 따옴표
- *구도(Composition)*: 템플릿마다 정해 둔 영문 묘사(`HINTS`). "왼쪽→오른쪽 N단계, 각 단계는 번호 뱃지 위 카드, 게이트 삼각형은 `after` 단계 뒤 화살표 위" 처럼 **배치 규칙**을 말한다. 자유 도식은 spec의 `image_layout` 필드에 직접 쓴다
- *내용(Content)*: spec을 계층 목록으로 펼친다. 필드 이름은 그대로 두되 "필드 이름은 그리는 글자가 아니다"라고 못박는다. `_level` 같은 판정값은 남기고 `_lane`·`_w` 같은 좌표 보정값은 뺀다

**③ STYLE** — 프리셋 토큰에서 자동으로 뽑는다. 손으로 쓰지 않는다.
- 팔레트: 주색·보조·표지·옅은 틴트·테두리·강조·본문·보조 글자의 **hex 전부** + "이 밖의 색 금지"
- 모서리(`--radius-box` → sharp / slightly / softly / generously rounded), 그림자 유무, 바탕(흰색 / 옅은 패널)
- 강조 방식(`--strong-ring` → 칠함 / 외곽선), 제목 글꼴(명조 여부), 제목 정렬·장식, 뱃지 모양
- 분위기 문장: 프리셋 머리의 `@image-style:` 한 줄

**④ TEXT RULES** — 넣을 문자열을 **번호 붙여 전수** 나열하고 "정확히 이것만, 글자 그대로, 번역·의역·채움말·영문·로고·워터마크 금지, 줄바꿈 유지". 이 목록이 곧 OCR 대조표다.

**⑤ AVOID** — 3D·아이소메트릭·그라데이션·사진·클립아트 인물·장식 배경·목록 밖 글자.

### 설계 원칙

- **내용은 spec에서만.** 프롬프트에 없는 내용을 모델이 채우지 않게, 넣을 글자를 전수로 준다
- **스타일은 프리셋에서만.** 코드 렌더와 이미지 모델 그림이 한 문서에 섞여도 같은 집안으로 보이는 이유
- **배치는 규칙으로 말한다.** "예쁘게"가 아니라 "몇 개가 어느 방향으로 어떻게 이어지는가"
- **영어로 쓰고 한글은 따옴표 안에만.** 지시문과 그릴 글자가 섞이지 않는다

## 모델 선택

`--model auto` (기본) — `/v1/models` 목록에서 `gpt-image-<버전>[-<변형>]` 중 가장 높은 버전을 고른다. 날짜 스냅샷과 `mini`는 제외. 같은 버전 안에서는:

| 모드 | 우선순위 | 이유 |
|---|---|---|
| 기본 | sunburst → (무변형) → flare | 도식은 작은 글자·가는 선이 많아 세밀함이 우선 |
| `--fast` | flare → (무변형) → sunburst | 시안을 여러 장 빨리 볼 때 |

목록은 하루 동안 `~/.cache/doc-figure/models.json` 에 캐시된다. 새 모델이 나오면 다음 날부터 자동으로 따라간다. 특정 모델로 고정하려면 env `FIGURE_IMAGE_MODEL`.

## 받은 이미지 점검 — 순서대로

1. **스크립트 OCR 결과를 본다.** macOS Vision(1순위) 또는 tesseract로 대조해 ✓/△/✗ 를 낸다. Vision 기준 실측 정확도: 44건 중 43, 39건 중 37~38, 20건 중 20. 남는 △는 대개 ▲·→ 같은 기호다
2. **이미지를 직접 열어 모든 라벨을 읽는다.** OCR ✓ 여도 숫자·조사 하나가 틀릴 수 있고, △·✗ 여도 멀쩡할 수 있다. 이 단계를 건너뛰고 "완성"이라 말하지 않는다
3. **개수·연결을 센다.** 부문 6개가 6개인가, 화살표 방향이 맞는가, 강조(highlight)가 지정한 곳에 갔는가
4. **팔레트를 본다.** 프리셋 밖 색이 끼었는가. 판정 단계 색이 뒤바뀌지 않았는가 (실측: 3단계를 프리셋 주황 대신 차콜로 칠한 사례 → `--fix` 한 번으로 해결)
5. 틀렸으면 `--fix`. 두 번 고쳐도 안 되면 코드 렌더로 돌아간다

## 키 없이 쓰기

```bash
python3 scripts/gen_image.py <spec.json> --preset <프리셋> --dry-run > prompt.txt
```

`prompt.txt` 를 ChatGPT(이미지 생성)에 그대로 붙여 넣으면 같은 설계의 그림이 나온다. 점검 절차는 위와 같다.

## 글자 없는 삽화 (표지 배경·장 도입 이미지)

도식이 아니라 분위기 이미지가 필요할 때의 골격. 이때는 **글자를 하나도 넣지 않는다.** 캡션은 문서 편집기에서 단다.

```
[대상] , [구도] , [양식] , [색] , [배경] , [금지]
```

| 자리 | 예 |
|---|---|
| 대상 | `an abstract network of connected nodes spreading across the frame` |
| 구도 | `centered composition, generous negative space` |
| 양식 | `flat vector illustration, minimal geometric shapes, no gradients` |
| 색 | 프리셋 주색 hex 2~3개로 고정 |
| 배경 | `plain white background` 또는 프리셋 `--bg` |
| 금지 | `no text, no letters, no numbers, no logos, no watermark` |

**금지 절을 생략하지 않는다.** 빼면 모델이 글자처럼 보이는 형체를 넣는다.

## 문서에 넣을 때

- 산출 경로(코드 렌더 / 이미지 모델 + 모델 id)를 삽입 가이드에 적는다
- 생성 이미지임을 밝혀야 하는 발주처가 있다. 확인한다
- `.prompt.txt` 와 `.meta.json` 을 spec 옆에 남긴다. 재생성·수정의 근거다

## v2.0 — 프리셋이 규율 절을 고른다

프리셋 머리 주석에 `@image-discipline: kr-gov`가 있으면(`house`·`house-report`) 프롬프트 끝의 규율 절이 **KR-GOV DIAGRAM DISCIPLINE**으로 바뀐다. 잘 그린 국내 공공 도식 57장과 사용자 채택본에서 잰 문법을 문장으로 옮긴 것이다 — [benchmark-kr-2026.md](benchmark-kr-2026.md).

| 절 | 요지 |
|---|---|
| 두 층 채움 | 진한 머리띠·이름표 + 같은 색 옅은 몸 + 흰 안쪽 카드, 색 면적 15~25% |
| 뜻 있는 색 | main=핵심, teal=산출·통과, amber=주의·예시, red 점선=탈락, 파랑 계열 밖 강조는 하나 |
| 격자 변화 | 1→3→2열, 왼쪽 이름표 열, 같은 상자 반복 격자 금지, 여백은 묶음 바깥 |
| 아이콘·번호 | spec에 있는 것만 — 선 아이콘은 tone 색 얇은 획으로 카드당 하나, 번호는 목록에 있는 것만 |
| 인쇄 글자 | 라벨이 그림 폭의 약 1.4% 이상 |
| 금지 | 3D·등각·광택 구슬·그라데이션·사진·클립아트 인물·장식 배경 |

그 밖의 프리셋은 종전 **PRINT-FIGURE DISCIPLINE**(2010년대 인쇄 도판 — 아이콘·번호 뱃지 금지)을 쓴다. board spec은 `HINTS["board"]`가 배치 트리(row·col·group·band·steps·chips·diamond·timeline·kv·links)를 읽는 법과 `tone`의 뜻을 설명하고, 배치 키(`gap`·`widths`·`via`·`offset` …)는 내용 목록에서 뺀다.
